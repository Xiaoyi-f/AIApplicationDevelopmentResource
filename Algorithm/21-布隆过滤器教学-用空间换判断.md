## 一、布隆过滤器是什么

**布隆过滤器 = 一个「位数组 + 多个哈希函数」的组合，用来判断「一个值一定不存在 / 可能存在」。**

注意它的判断结果是**不对称**的：

| 判断结果 | 含义 | 准确度 |
| --- | --- | --- |
| 返回「不存在」 | **一定不存在** | 100% 准确 |
| 返回「存在」 | **可能存在**（有小概率误判） | 可能有误判 |

> 一句话：**布隆过滤器「说不存在就肯定不存在，说存在只是可能」**。这是它最核心的特性。

**为什么用它**：判断一个数据是否在海量数据里，直接查数据库/内存太贵。布隆过滤器用极小空间（远小于存全部数据）就能「拦住大部分不存在的请求」，减少缓存穿透。

## 二、核心原理

布隆过滤器的核心是**一个位数组 + 多个哈希函数**：

1. **插入**：对元素算 k 个哈希值，把这 k 个位置的位都置为 1。
2. **查询**：再算这 k 个哈希值，看对应位置是否**都是 1**。
   - 有任意一个是 0 → **一定不存在**（因为插入时这 k 个位都会置 1）。
   - 全是 1 → **可能存在**（可能这些 1 是别的元素凑出来的，即「误判」）。

**为什么会有误判**：不同的元素可能哈希到相同的位。多个元素把某些位置都置 1 后，一个「没插入过的元素」也可能刚好命中全是 1 的位置。

## 三、完整实现

> ⚠️ 你原笔记这里有个变量名笔误：`__init__` 里写的是 `self.big_array`，但 `add`/`contains` 里用的是 `self.bit_array`，会导致 `AttributeError` 报错。下面已统一为 `self.bit_array`。

```python
# 布隆过滤器
import math
import hashlib

class BloomFilter:

    def __init__(self, n = 10000, p = 0.01):
        # n 预估元素数量 / p 期望误判率
        self.size = int(-n * math.log(p) / (math.log(2) ** 2))
        self.k = int(self.size / n * math.log(2))
        self.bit_array = [0] * self.size

    def _hash(self, source_data, seed):
        # md5 算法 数学不可逆
        h = hashlib.md5((str(seed) + source_data).encode()).hexdigest()
        return int(h, 16) % self.size

    def add(self, item):
        for i in range(self.k):
            idx = self._hash(item, i)
            self.bit_array[idx] = 1

    def contains(self, item):
        for i in range(self.k):
            idx = self._hash(item, i)
            if self.bit_array[idx] == 0:
                return False
        return True

# 测试
if __name__ == "__main__":
    bf = BloomFilter(n=1000, p=0.01)
    bf.add("apple")
    bf.add("banana")
    print(bf.contains("apple"))   # True（存在）
    print(bf.contains("orange"))  # False（不存在）
```

**核心理解**：
- `size` = 位数组长度，`k` = 哈希函数个数，都根据「预估元素数量 n」和「误判率 p」自动算出。
- 用 MD5 + 不同 `seed` 来模拟「多个不同的哈希函数」。
- MD5 是**数学不可逆**的，适合做哈希。

## 四、两个关键参数（误判率）

```python
self.size = int(-n * math.log(p) / (math.log(2) ** 2))  # 位数组大小
self.k = int(self.size / n * math.log(2))               # 哈希函数个数
```

| 参数 | 含义 | 影响 |
| --- | --- | --- |
| `n` | 预估要存的元素数量 | 越大，位数组要越大 |
| `p` | 期望误判率 | 越小，位数组越大、哈希函数越多 |

**权衡关系（面试常问）**：
- **误判率 p 越小** → 位数组 size 越大、哈希函数 k 越多 → 空间占用越大。
- **误判率 p 越大** → 空间小，但误判多。

> 一句话：**布隆过滤器是「空间」和「误判率」的权衡。** 空间给得越足，误判越低，但永远不可能降到 0（这是它「允许误判」的代价，换来了极小的空间占用）。

## 五、适用场景

布隆过滤器的核心价值是**拦住「一定不存在」的数据，减少对后端的无效访问**：

| 场景 | 怎么用 |
| --- | --- |
| **缓存穿透** | 先查布隆过滤器，不在就直接返回，不打到数据库 |
| **爬虫去重** | 判断 URL 是否已抓过（误判顶多少抓一个，可接受） |
| **黑名单过滤** | 快速判断某个值是否在黑名单（误判=可能误拦，可接受） |
| **垃圾邮件过滤** | 快速判断邮件地址是否在垃圾名单 |

> 关键认知：**布隆过滤器适合「允许少量误判」的场景**。凡是「误判会导致严重后果」的场景（如「判断用户是否已付款」），就不能用布隆过滤器，得用精确的集合。
