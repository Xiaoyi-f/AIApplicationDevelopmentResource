## 一、先建立整体认知

数据结构按「逻辑关系」分四大类，九大结构都能归进去：

| 类别 | 包含 | 核心特征 |
| --- | --- | --- |
| **线性结构** | 线性表、栈、队列、串 | 数据「一对一」排成一行 |
| **散列结构** | 哈希表 | 靠哈希函数「算」出位置 |
| **树形结构** | 二叉树、B/B+ 树、红黑树 | 数据「一对多」分层 |
| **图形结构** | 图 | 数据「多对多」任意相连 |

> 记忆：**线性排一行，哈希算位置，树分层，图乱连。**

---

## 二、线性表：顺序表 + 链表

**线性表 = 数据排成一行**，有两种实现：

| 实现 | 底层 | 特点 |
| --- | --- | --- |
| **顺序表**（数组） | 连续内存 | 随机访问 O(1)，插入删除 O(n) |
| **链表** | 节点 + 指针 | 随机访问 O(n)，插入删除 O(1) |

**怎么选**：
- 频繁「按位置查」→ 数组
- 频繁「头尾插入删除」→ 链表

> 一句话：**数组像一排固定座位（找第几个快），链表像一串珠子（中间插拔快）。**

---

## 三、栈和队列

| 结构 | 规则 | 英文 | 应用 |
| --- | --- | --- | --- |
| **栈** | 后进先出 | FILO | 函数调用、括号匹配、DFS |
| **队列** | 先进先出 | FIFO | 任务排队、BFS、消息队列 |

> 一句话：**栈像一摞盘子（后放的先拿），队列像排队（先来的先办）。**

---

## 四、串（字符串）

**串 = 字符组成的线性表**，特殊在「处理对象是字符序列」。

- 常用操作：子串查找（KMP）、前缀匹配（字典树 Trie）、回文判断。
- 注意：串的很多算法（KMP、字典树）是独立主题，这里先记住「串是字符的线性表」即可。

---

## 五、数组和稀疏矩阵

- **数组**：用「索引」快速访问，是计算机里最基础的结构。
- **稀疏矩阵**：大部分元素是 0 的矩阵，如果按普通二维数组存，浪费大量空间。用「只存非零元素（行、列、值）」的方式压缩。

> 一句话：**稀疏矩阵 = 别把一堆 0 也存进去，只记「哪里有数」。**

---

## 六、哈希表

**哈希表 = 靠「哈希函数」把 key 算出一个位置，直接存取。**

两个核心概念（面试必考）：

| 概念 | 含义 |
| --- | --- |
| **哈希函数** | key → 数组下标 的映射 |
| **哈希冲突** | 两个不同 key 算出同一个下标 |

**冲突怎么解决**：常见有「链地址法」（同位置的元素串成链表）、「开放寻址法」（冲突就往后找空位）。

> 一句话：**哈希表是「用空间换时间」的典型——O(1) 的查找速度，代价是可能冲突、且无序。**

---

## 七、树和二叉树

**树 = 一对多的分层结构**，根在上，往下分叉。

- **二叉树**：每个节点最多两个子节点。
- **核心套路**：递归。树的遍历（前序/中序/后序/层序）几乎都用递归实现。

| 遍历 | 顺序 | 口诀 |
| --- | --- | --- |
| 前序 | 根-左-右 | 先看自己 |
| 中序 | 左-根-右 | 先左后根 |
| 后序 | 左-右-根 | 最后看自己 |
| 层序 | 一层一层 | 用队列 |

> 一句话：**树的灵魂是「递归」，二叉树是树里最常见的特例。**

---

## 八、B 和 B+ 树

**B/B+ 树 = 多路平衡查找树**，专门为「磁盘存储」设计——因为磁盘读一次很慢，要尽量让每个节点多存几个 key，减少磁盘读写次数。

| 类型 | 特点 | 应用 |
| --- | --- | --- |
| **B 树** | 数据存在所有节点 | 文件系统 |
| **B+ 树** | 数据只在叶子节点，叶子用链表串起来 | **数据库索引（MySQL InnoDB）** |

**B+ 树两个关键设计（面试必考）**：
1. **索引在非叶子，数据在叶子**——非叶子节点只存 key 不存数据，一个节点能存更多 key，树更矮。
2. **叶子节点用链表串起来**——方便范围查询（`BETWEEN`、`ORDER BY`）。

> 一句话：**B+ 树是数据库索引的底层，核心是「让树矮 + 叶子串链」来加速磁盘查询和范围查询。**

## 九、图

**图 = 多对多的关系**，节点（顶点）之间用边任意连接。

**两种存储方式（面试必考）**：

| 存储 | 结构 | 适合 |
| --- | --- | --- |
| **邻接矩阵** | 二维数组 | 边密集、要快速判断两节点是否相连 |
| **邻接表** | 数组 + 链表 | 边稀疏、要遍历某节点的邻居 |

**核心算法**：DFS、BFS、最短路（Dijkstra）、最小生成树（Kruskal/Prim）、拓扑排序。

> 一句话：**图用「邻接矩阵（密）」或「邻接表（疏）」存，核心是 DFS/BFS 和各类路径算法。**

## 十、红黑树

**红黑树 = 自平衡的二叉查找树（BST）**，通过「染色 + 旋转」保证树的高度不会失衡，从而保证查找/插入/删除都是 O(log n)。

**五条性质（面试必考）**：

| # | 性质 | 白话 |
| --- | --- | --- |
| 1 | 非红即黑 | 每个节点要么红要么黑 |
| 2 | 根叶黑 | 根节点是黑，叶子（NIL）是黑 |
| 3 | 根红子黑 | 红节点的子节点必须是黑（红不能连续） |
| 4 | 黑高相同 | 任意节点到每个叶子，经过的黑节点数一样多 |
| 5 | — | （第 4 条保证「黑高相同」，树不会歪） |

> 一句话：**红黑树靠「红不连续 + 黑高相同」两条铁律，保证树平衡，是 Java TreeMap、HashMap（链表转红黑树）的底层。**

## 十一、九大结构速查表

| 结构 | 一句话 | 典型应用 |
| --- | --- | --- |
| 线性表 | 数据排一行 | 数组、链表 |
| 栈/队列 | 后进先出 / 先进先出 | 函数调用 / 任务排队 |
| 串 | 字符的线性表 | 文本处理 |
| 数组/稀疏矩阵 | 索引访问 / 压缩存非零 | 矩阵运算 |
| 哈希表 | 哈希函数算位置 O(1) | 缓存、去重 |
| 树/二叉树 | 一对多，递归 | 层级结构、查找 |
| B/B+ 树 | 多路平衡，矮树 | 数据库索引 |
| 图 | 多对多 | 社交网络、路径 |
| 红黑树 | 自平衡 BST | TreeMap、HashMap |
